● Ejecución controlada por el runtime
La idea central

Tener capacidad no significa tener autoridad.

Un agente puede decidir qué quiere hacer, pero nunca debe decidir por sí mismo qué tiene permitido hacer.

✓

El modelo propone. El runtime decide.

Cada solicitud de herramienta pasa por una validación de esquema y una autorización determinista antes de ejecutarse. Los permisos se definen en las políticas de la aplicación, no en las instrucciones ni en las respuestas generadas por el modelo.

01 / INTEGRACIÓN DE MODELOS

Elige modelos por capacidades

Una API de conversación común desacopla la ejecución de los agentes de los formatos específicos de cada proveedor. Los modelos compatibles se identifican y seleccionan mediante un registro configurable.

02 / HERRAMIENTAS CONTROLADAS

Herramientas como capacidades explícitas

Las definiciones tipadas de herramientas, la validación mediante JSON Schema y las listas de permisos por agente o globales mantienen las acciones externas bajo un control explícito.

03 / EJECUCIONES OBSERVABLES

Haz que la ejecución sea inspeccionable

Los eventos del runtime registran los pasos relevantes —incluidos el enrutamiento de modelos, las decisiones de alternativa y la ejecución de herramientas— para que cada ejecución sea algo más que una respuesta opaca.

04 / CICLO DE VIDA

Controla la ejecución

La configuración de agentes, los límites de ejecución, la cancelación y los tiempos de espera son responsabilidades del runtime, no instrucciones que se dejan a la interpretación del modelo.

05 / MODULARIDAD

Mantén límites claros

Los adaptadores de proveedores, el runtime y las integraciones de herramientas se organizan en crates independientes, con responsabilidades concretas y contratos documentados por separado.

06 / PERSISTENCIA

Avanza hacia la recuperación

La persistencia de ejecuciones, los puntos de control, los reintentos y la reanudación forman parte de la evolución prevista de la plataforma; no son funcionalidades que se presenten como terminadas.

Diseño del sistema

Responsabilidades bien separadas.

El runtime coordina la interacción. Los adaptadores conectan los modelos. Los crates de herramientas gestionan sus integraciones. Las políticas permanecen fuera del modelo.

ARQUITECTURA CONCEPTUAL · LA IMPLEMENTACIÓN EVOLUCIONA CON EL PROYECTO
Una ejecución, paso a paso

De la intención a la acción.

Una llamada a una herramienta es una solicitud, no una orden con privilegios implícitos.

Recibir

El runtime recibe la solicitud y la configuración del agente.

Razonar

Un modelo compatible responde o propone una llamada a una herramienta.

Validar

Los argumentos se comprueban frente al esquema declarado por la herramienta.

Autorizar

Las políticas del runtime determinan si la acción está permitida.

Ejecutar

La herramienta se ejecuta y su resultado vuelve a la conversación.

Estado del proyecto

En una fase inicial, con fundamentos ya funcionales.

El runtime de agentes y las integraciones de modelos ya funcionan. La orquestación de servicios, el almacenamiento y las capacidades del servidor se están incorporando de forma gradual. Consulta el repositorio para conocer la implementación actual y la documentación de cada crate.
