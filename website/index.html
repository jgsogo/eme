● Execution controlled by the runtime
The core idea

Capability is not authority.

An agent can decide what it wants to do. It should never decide, by itself, what it is allowed to do.

✓

The model proposes. The runtime decides.

Every tool request passes through schema validation and deterministic authorization before execution. Permissions live in application policy—not in the model's instructions or generated output.

01 / MODEL INTEGRATION

Choose models by capability

A common conversation API separates agent execution from provider-specific formats. Compatible models can be discovered and routed through a configured registry.

02 / CONTROLLED TOOLS

Tools as explicit capabilities

Typed tool definitions, JSON Schema validation and per-agent or global allow-lists keep external actions behind a clear boundary.

03 / OBSERVABLE RUNS

Make execution inspectable

Runtime events capture meaningful steps—including model routing, fallback decisions and tool execution—so a run is more than an opaque response.

04 / LIFECYCLE

Control the execution

Agent configuration, execution limits, cancellation and timeouts are runtime responsibilities, not prompts left for a model to interpret.

05 / MODULARITY

Keep boundaries explicit

Provider adapters, the runtime and tool integrations live in separate crates with focused responsibilities and independently described contracts.

06 / DURABILITY

Build towards recovery

Persistent runs, checkpoints, retries and resumption are part of the platform's direction—not capabilities claimed as complete today.

System design

Separation by responsibility.

The runtime coordinates the interaction. Adapters connect models. Tool crates own integrations. Policy stays outside the model.

An execution, step by step

From intent to action.

A tool call is a request—not a command with implicit privileges.

Receive

The runtime accepts the request and agent configuration.

Reason

A compatible model responds or proposes a tool call.

Validate

Arguments are checked against the tool's declared schema.

Authorize

Runtime policy determines whether the action is allowed.

Execute

The tool runs; its result returns to the conversation.
